# Найденные ошибки

Вариант **seed 42**, второй ноутбук. Найдено ровно **3** семантические ошибки.
До исправлений проходило **7 из 17** проверок, после — **17 из 17**.

| № | Локализация | Механизм нарушения работы алгоритма | Способ исправления |
|---|---|---|---|
| 1 | `LayerNorm.forward`, строки 60–61 в `notebooks/dz1-bughunt.ipynb` (ячейка `c023`): `x.mean(dim=0)` и `x.var(dim=0)` | Среднее и дисперсия считаются по оси батча, а не по оси признаков токена. Для входа `(B, L, D)` это batch-нормировка: статистики каждого канала усредняются по всем примерам и позициям батча, поэтому токен нормируется не сам по себе, а относительно соседей. При генерации `B=1` среднее по единственному элементу равно самому `x`, дисперсия равна нулю, и `(x − mean) / sqrt(0 + eps) = 0`: слой возвращает только `bias`, вход перестаёт влиять на выход. При нулевом `bias` логиты всех позиций одинаковы, softmax равномерен, top-k выбирает случайный токен. На обучении результат зависит от состава батча — возникает рассогласование train/inference. | В `mean` и `var` заменить `dim=0` на `dim=-1`: статистики считаются по `D` признакам каждого токена независимо. |
| 2 | `scaled_dot_product_attention`, строка 101 в `notebooks/dz1-bughunt.ipynb` (ячейка `c023`): `torch.softmax(scores, dim=-2)` | Softmax берётся по оси запросов, а не ключей. Матрица `scores` имеет форму `(B, H, L_q, L_k)`; при нормировке по запросам каждая строка-запрос перестаёт быть распределением по ключам: сумма весов по ключам не равна единице, выход внимания — не выпуклая комбинация `value`, а его масштаб зависит от позиции. Вес ключа `j` нормируется по всем запросам, включая будущие `i > текущего`, поэтому изменение будущего токена меняет веса в прошлых позициях: причинная маска не спасает, информация течёт из будущего. На обучении модель использует этот «подсмотр» (teacher forcing), а при авторегрессионной генерации будущих токенов нет — распределение входов резко отличается, и генерация рассыпается. | Заменить `dim=-2` на `dim=-1`: softmax по последней оси (ключам), каждая строка матрицы внимания — распределение с суммой 1. |
| 3 | `sinusoidal_positional_encoding`, строка 39 в `notebooks/dz1-bughunt.ipynb` (ячейка `c023`): `torch.arange(1, length + 1)` | Позиции начинаются с 1 вместо 0. Токен с индексом `p` получает фазу `(p+1)ω`: первый токен кодируется как вторая позиция, а последний — фазой `length`, выходящей за спроектированный диапазон `0..length−1`. Пропадает нулевой якорь (`sin 0 = 0`, `cos 0 = 1`), абсолютная позиционная разметка систематически смещена на единицу. Относительные расстояния при глобальном сдвиге сохраняются, поэтому эффект мягче двух других ошибок, но контракт функции нарушен: модель обучается на неверных абсолютных позициях, а проверки фиксируют расхождение с формулой. | Заменить `torch.arange(1, length + 1)` на `torch.arange(0, length)`: позиция 0 даёт `sin = 0`, `cos = 1`, как в формуле «Attention is All You Need». |

## Почему этого достаточно

Все три ошибки семантические: код запускается, модель обучается, потери падают, но
вычисляется не то, что заявлено в docstring. Первая ломает нормировку активаций и при
`B=1` полностью обнуляет сигнал, вторая нарушает причинность и распределение весов
внимания, третья сдвигает входное представление позиции. После исправления всех трёх
проверки зелёные, потери падают на обучении и валидации, а генерация воспроизводит
структуру корпуса.

Показательная деталь: проверка `no_future_leak_in_model` на исходном коде формально
проходила, потому что ошибка LayerNorm при `B=1` обнуляла логиты и маскировала утечку.
После исправления LayerNorm она стала бы падать — поэтому обе ошибки нужно исправлять
вместе.
